# avtokino

Собирает один видеоролик из фото и видео в каталоге события. В комплекте отдельная утилита
`avtokino.tools` с командами для отдельных файлов: вырезать кусок, перевернуть, собрать таймлапс,
свести две камеры по звуку и смонтировать из них общий ролик. Работает на Ubuntu 24 и Windows 10.

## Установка

Нужны Python 3.10+ и ffmpeg (вместе с ffprobe).

Ubuntu 24:

```bash
sudo apt install ffmpeg python3-venv
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
```

Windows 10: поставьте Python с python.org и ffmpeg (сборка «full» с gyan.dev), добавьте `ffmpeg\bin` в PATH
или передавайте путь через `--ffmpeg` и `--ffprobe`. Затем `pip install -r requirements.txt`.

Зависимости: Pillow; pillow-heif (фото HEIC с iPhone, необязательно); tzdata (только Windows, для `--tz`);
numpy (только для команд `sync` и `multicam`).

## Сборка ролика события

### Запуск

```bash
python -m avtokino /data/20240615_Wedding
python -m avtokino /data/20240615_Wedding --music /data/music --music-shuffle --title
python -m avtokino /data/20240615_Wedding --caption --caption-name "Свадьба" --caption-duration 30
python -m avtokino /data/20240615_Wedding --dry-run      # только план и лог
```

Имя каталога: `ГГГГММДД_Название`, период `ГГГГММДД-ДД_Название` или `ГГГГММДД-ММДД_Название`,
только месяц `ГГГГММ_Название` или `ГГГГММXX_Название` (день неизвестен).

Ролик `20240615_Wedding.mp4` и лог `20240615_Wedding.log` появятся в самом каталоге события.
Если ролик уже есть, создаётся `20240615_Wedding_v2.mp4` и т. д. Ранее собранные ролики в монтаж не попадают.
Запуск ручной, на один каталог.

### Как это работает

1. **Сканирование.** Обходятся все подкаталоги (кроме исключённых через `--exclude`). Видео короче
   `--min-clip` (5 с) пропускаются, заодно отсекаются «живые фото» iPhone.
2. **Даты.** Приоритет: метаданные (EXIF, QuickTime, дата AVCHD внутри .MTS) → дата в имени файла →
   дата файла. Часовой пояс определяется сам; подробнее в разделе [даты и часы камер](#даты-и-часы-камер).
   Файлы идут по времени.
3. **Базовые параметры.** Разрешение, соотношение сторон, кодек и частота кадров берутся у самого
   большого горизонтального видео (вертикальное — только если горизонтальных нет), так что ролики того же
   формата копируются без перекодировки. Остальные вписываются с чёрными полями.
   `--resolution 2704x2028` (или `2704:2028`) — точное разрешение с любым соотношением сторон.
   `--aspect 16:9` — соотношение сторон: кадр самого большого видео достраивается полями до нужной
   пропорции без уменьшения (2704x2028 при `--aspect 16:9` даёт 3606x2028). Вместе эти две опции не используются.
4. **Видео** копируется без перекодировки, если совпадает кодек, разрешение, частота кадров (±1%),
   нет поворота, HDR, чересстрочности и битрейт не выше `--vbitrate`. Иначе перекодируется
   с качеством CRF и потолком `--vbitrate`, с чёрными полями при другом соотношении сторон.
   HDR переводится в SDR.
5. **Фото** — кадр с плавным зумом 5% (приближение и отдаление по очереди), 5 с;
   в серии больше 5 фото подряд — по 3 с. Ориентация из EXIF учитывается.
6. **Звук** всегда пересобирается в одну дорожку AAC 48 кГц 192k: живой звук клипов, тишина под фото.
   Музыка из `--music` идёт по алфавиту (или в случайном порядке с `--music-shuffle`) по кругу,
   с выравниванием громкости, перекрытием треков, приглушением под живым звуком (`--no-ducking`
   отключает) и затуханием в конце.
7. Сегменты склеиваются через MPEG-TS, поэтому клипы с разных камер стыкуются без перекодировки.

В логе: найденные файлы и даты, часовой пояс, хронология, список длинных видео (`--long-video`,
больше 1 мин), план обработки с причиной перекодировки каждого клипа, расчётные длительность и размер.

### Даты и часы камер

- **Часовой пояс** определяется по файлам, где он записан явно (EXIF OffsetTime, iPhone, AVCHD),
  и по видео, у которых есть и UTC-метка, и местное время в имени или дате файла. Если не вышло,
  берётся `--tz` (`Europe/Moscow` или `+03:00`) или пояс компьютера. GoPro пишет местное время
  с пометкой UTC, это учитывается.
- **Файлы вне периода события.** Если дата файла выходит за период из имени каталога (с запасом
  `--date-tolerance`, по умолчанию 6 ч; для `ГГГГММ`/`ГГГГММXX` — весь месяц), файл ставится в конец
  ролика; такие файлы между собой тоже идут по времени.
- `--time-fix "БЫЛО -> СТАЛО"` — поправка сбитых часов устройства: что показывали часы и сколько было
  на самом деле, например `--time-fix "2016-01-04 23:02:42 -> 2025-06-20 09:48:00"`. Пробуется только
  на файлах вне периода события; если с ней файл попадает в период, он получает исправленное время.
  Поправок может быть несколько, применяется первая подошедшая.
- `--shift "МАСКА=СЕК"` — сдвинуть дату съёмки файлов по маске на СЕК секунд (минус — назад):
  `--shift "DSC*.jpg=-3600"`, `--shift "Olympus/*=10800"`. Маска без «/» сравнивается с именем файла,
  с «/» — с путём от каталога события; регистр не важен. Применяется до проверки периода и `--time-fix`.
  Можно указать несколько, к файлу применяется первый подошедший. Точную поправку для второй камеры
  подсказывает команда [sync](#sync-рассинхронизация-двух-камер-по-звуку).

### Оформление

- `--caption` — подпись в правом нижнем углу: название и дата, выровнены по правому краю, белый текст
  с чёрной обводкой. Показывается первые `--caption-duration` секунд (10), плавно появляется и исчезает.
  Текст по умолчанию берётся из имени каталога («Август 2014», «31 июля – 3 августа 2014»),
  заменить: `--caption-name "Корпоратив DNS. Теплое море."`, `--caption-date "Август 2014"`.
  Шрифт: `--caption-font Roboto-Regular.ttf`. Видео, на которые попадает подпись, перекодируются.
  Если включён титр, подпись появляется сразу после него.
- `--title` — титр в начале с названием и датой события; `--title-text СТРОКА` — свой текст, каждый
  `--title-text` даёт отдельную строку, первая крупнее (включает титр сам). Длительность: `--title-duration 4`.
- `--photo-fit cover` — фото на весь кадр с обрезкой краёв; по умолчанию `contain` (целиком, с полями).
  Вертикальные фото даже в режиме `cover` вставляются целиком, с полями.
- `--gopro-trim [СЕК]` — отрезать конец у роликов GoPro (по именам `GOPR0123`, `GP010123`, `GH010123`,
  `GX010123`), без числа 3 с: убирает момент выключения камеры рукой. `--min-clip` для GoPro
  проверяется уже после обрезки.
- `--transition fade` — переходы через чёрное (`--transition-duration`, 0,5 с); перекодирует все клипы.

### Все параметры

Полный список с описаниями: `python -m avtokino --help`.

**Время в параметрах.** Везде, где параметр задаёт время в секундах (длительности, сдвиги, обрезка),
его можно писать числом секунд или как `ЧЧ:ММ:СС` / `ММ:СС`: `90`, `2.5`, `1:30`, `01:30:00`,
`0:00:05.5`. Где допустим сдвиг назад — со знаком: `--shift "DSC*.jpg=-1:00:00"`.
`--date-tolerance` задаётся в часах: `6`, `1.5` или `1:30`. Это относится и ко всем командам
`avtokino.tools`: `trim ФАЙЛ 1:05-1:20`, `multicam --switch 0:10`, `sync --max-offset 5:00`.

| Группа | Параметры (по умолчанию) |
|---|---|
| Видео | `--resolution 1920x1080` (любое соотношение), `--aspect 16:9`, `--fps 25` или `30000/1001`, `--vcodec h264\|hevc`, `--vbitrate 12M` (потолок; без него только CRF), `--crf` (h264: 20, hevc: 22), `--preset` (medium; быстрее — veryfast), `--safe` (перекодировать всё) |
| Звук | `--acodec` (aac), `--abitrate` (192k), `--arate` (48000), `--achannels` (2), `--volume` (1.0) |
| Музыка | `--music КАТАЛОГ`, `--music-volume` (0.3), `--music-crossfade` (3 с), `--music-fadeout` (5 с), `--music-shuffle`, `--no-ducking` |
| Фото | `--photo-duration` (5 с), `--photo-burst-duration` (3 с), `--photo-burst-threshold` (5 фото), `--photo-zoom` (1.05 = 5%), `--photo-fit` (contain) |
| Отбор | `--exclude КАТАЛОГ` (имя на любом уровне, путь `Mobile/Screenshots` или маска `*_old`; можно повторять), `--min-clip` (5 с), `--gopro-trim [3]`, `--long-video` (60 с, 0 — не выводить) |
| Даты | `--tz`, `--date-tolerance` (6 ч), `--time-fix`, `--shift` |
| Оформление | `--title`, `--title-text`, `--title-duration` (4 с), `--caption`, `--caption-name`, `--caption-date`, `--caption-duration` (10 с), `--caption-font`, `--transition none\|fade`, `--transition-duration` (0,5 с) |
| Работа | `--jobs` (2 параллельных рендера), `--temp-dir` (по умолчанию в каталоге события), `--keep-temp`, `--dry-run`, `--ffmpeg`, `--ffprobe`, `-v` (подробный вывод), `--version` |

Видеокарта для кодирования не используется: на проверенных машинах x264 на процессоре быстрее
(`--preset veryfast` ускоряет примерно вдвое ценой чуть большего размера файла).

## Утилита avtokino.tools

Отдельная утилита для работы с файлами: `python -m avtokino.tools <команда> ...`.
Список команд: `python -m avtokino.tools -h`, справка по команде: `python -m avtokino.tools trim -h`.
Общие параметры (до имени команды): `--ffmpeg`, `--ffprobe`. Маски файлов (`*`, `?`) утилита раскрывает
сама, так что в Windows они тоже работают; маску лучше брать в кавычки.

| Команда | Что делает | Перекодирует |
|---|---|---|
| `trim` | вырезает один или несколько кусков видео | нет |
| `timelapse` | ролик из последовательности фото, одно фото = один кадр | да |
| `rotate180` | переворачивает видео на 180° | нет |
| `sync` | точный сдвиг между двумя камерами по звуку | — |
| `multicam` | общий ролик из двух камер с переключением | да |
| `pano360` | ролик из панорам 360: облёт в обычном кадре или полноценный 360 | да |

### trim: вырезать куски видео

Режет без перекодировки (`-c copy`), сохраняет метаданные (модель камеры, потоки GoPro). За один запуск
можно вырезать несколько кусков. Результат кладётся рядом с исходником:
`<имя>_trim_<ММ>m<СС>-<ММ>m<СС>.<расширение>` (минуты и секунды с ведущими нулями).

```bash
python -m avtokino.tools trim GOPR4745.MP4 10-25                      # GOPR4745_trim_00m10-00m25.MP4
python -m avtokino.tools trim GOPR4745.MP4 1:05-1:20 2:30-3:10 5:00-  # три куска, последний до конца файла
python -m avtokino.tools trim GOPR4745.MP4 --start 10 --end 25        # то же, что 10-25
python -m avtokino.tools trim 00082.MTS --cut-start 3                 # 00082_trim_start00m03.MTS
python -m avtokino.tools trim 00082.MTS --cut-start 3 --cut-end 2     # 00082_trim_start00m03_end00m02.MTS
```

- Куски задаются как `НАЧАЛО-КОНЕЦ` в секундах или `ММ:СС` / `ЧЧ:ММ:СС`; без конца (`5:00-`) — до конца
  файла. Дробные секунды попадают в имя как `00m08.5`. `--start/--end` — ещё один кусок,
  `--cut-start/--cut-end` — сколько отрезать от начала и конца; с `--start/--end` они вместе не используются.
- **Даты.** Дата съёмки в метаданных (`creation_time`, у iPhone ещё `creationdate`) сдвигается на время
  начала куска. Даты файла тоже пересчитываются от исходника: «создан» — начало куска, «изменён» —
  его конец (как у камер, где дата изменения файла — конец записи). У .MTS дата съёмки записана
  внутри видеопотока и сама соответствует началу куска.
- Без перекодировки кусок может начаться только с ключевого кадра, поэтому начало обычно получается
  на долю секунды (у AVCHD до 1 с) раньше заданного; утилита пишет, на сколько, а даты считает
  от фактического начала.
- Субтитры .MTS (наложение даты у Sony) не переносятся: ffmpeg не умеет их записывать.
- Существующий результат не перезаписывается без `--force`.
- Если и исходник, и вырезанный кусок лежат в каталоге события, в ролик попадут оба. Исходник
  лучше убрать в подкаталог и исключить через `--exclude`.

### timelapse: ролик из последовательности фото

Одно фото = один кадр. Берутся все фото каталога в порядке имён (`IMG_9` раньше `IMG_10`).
Ролик `<каталог>.mp4` сохраняется в том же каталоге (если такой уже есть, то `<каталог>_v2.mp4` и т. д.).

```bash
python -m avtokino.tools timelapse E:\photo\20240601_Sunset                          # 15 кадр/с, размер фото, до 15 Мбит/с
python -m avtokino.tools timelapse E:\photo\20240601_Sunset --fps 25 --resolution 1920x1080 --max-bitrate 10
```

- `--fps` — частота кадров (15);
- `--resolution ШxВ` — размер кадра (по умолчанию как у первой фотографии); фото другого формата
  вписываются целиком с чёрными полями; для кадра больше 4K утилита предупреждает, что его тянут не все плееры;
- `--max-bitrate МБИТ` — максимальный видеопоток в Мбит/с (15);
- `--crf` (20), `--preset` (medium), `--vcodec h264|hevc` — качество, скорость и кодек.

Битое фото пропускается, вместо него повторяется предыдущий кадр. Дата съёмки первого фото
записывается в метаданные ролика, так что avtokino поставит его на правильное место в хронологии.

### rotate180: перевернуть видео

Без перекодировки: в контейнере меняется только пометка поворота, её учитывают плееры и сам avtokino.
Метаданные и даты файла сохраняются. Результат: `<имя>_rotate180.<расширение>` рядом с исходником.
Можно передать несколько файлов или масок.

```bash
python -m avtokino.tools rotate180 E:\video\GOPR4745.MP4
python -m avtokino.tools rotate180 "E:\video\GOPR*.MP4" "E:\video\0008?.MTS"
```

- Повторный поворот уже повёрнутого файла возвращает его в нормальное положение.
- В .MTS, .AVI и .MKV пометки поворота нет, поэтому такие файлы сохраняются в MP4 (поток не
  перекодируется, меняется только контейнер, субтитры .MTS не переносятся). Дата съёмки
  записывается в метаданные MP4.
- Файлы с `_rotate180` в имени по маске не берутся; существующий результат не перезаписывается без `--force`.
- Результат может быть заметно меньше исходника, хотя видео то же самое: некоторые камеры (например,
  SJCAM) заранее резервируют место в файле, а пустой остаток при перезаписи не переносится.

### sync: рассинхронизация двух камер по звуку

Для двух роликов, снятых одновременно разными камерами, находит точный сдвиг между ними по звуку
(точность лучше 0,01 с, то есть меньше кадра). Нужен numpy.

```bash
python -m avtokino.tools sync E:\video\00082.MTS E:\video\GOPR4745.MP4
```

Пример ответа:

```
A начал запись на 3.470 с раньше B: один и тот же звук в A на 3.470 с дальше от начала.
Момент 0:00.000 в A соответствует −0:03.470 в B.
  в кадрах A (50.000 кадр/с): 173.5
  в кадрах B (29.970 кадр/с): 104.0
Уверенность: надёжно (кусков по 30 с, согласных со сдвигом: 18 из 18; чёткость пика 1.9)
По метаданным B начат на +12.00 с относительно A, по звуку на +3.470 с.
Чтобы avtokino считал время B по часам A: --shift "GOPR4745.MP4=-8.53"
```

- Ролик B режется на куски по 30 с, каждый кусок ищется во всём ролике A, и куски голосуют за сдвиг.
  Поэтому годится любой сдвиг, частичное перекрытие, шум и уход часов камер. Затем сдвиг уточняется
  на общем участке.
- Если часы камер заметно расходятся, команда пишет сдвиг в начале и в конце общего участка.
- Если общего звука не нашлось, уверенность «ненадёжно», поправка не предлагается, код выхода 3.
- `--max-offset СЕК` ограничивает поиск, `--max-duration СЕК` читает только начало очень длинных файлов.

### multicam: общий ролик из двух камер

Берёт файлы двух камер по маскам, находит одновременно снятые, точно сводит их по звуку (как `sync`)
и для каждой группы пересекающихся файлов собирает ролик, где камеры чередуются каждые 5 с.
Нужен numpy.

```bash
python -m avtokino.tools multicam "E:\video\GOPR*.MP4" "E:\video\SJCM*.mp4" --dry-run       # сначала отчёт и план
python -m avtokino.tools multicam "E:\video\GOPR*.MP4" "E:\video\SJCM*.mp4" --offset +3:07
```

- **Время файлов** берётся из метаданных, как в avtokino. `--offset` — примерно на сколько часы B
  отстают от A (если спешат: `--offset=-3:07`, со знаком «=»). Точный сдвиг ищется по звуку в пределах
  `--search` (±60 с) от времени по метаданным.
- **Без `--offset`** тоже работает: если в окне ±60 с общего звука нет, сдвиг ищется без ограничений,
  и с найденной поправкой пары подбираются заново. Команда пишет поправку, которую можно указать в
  следующий раз.
- **Группа** — цепочка пересекающихся файлов (A1 с B1, B1 с A2…). Ролик покрывает всю группу; где снимает
  одна камера, показывается она. `--overlap-only` — только время, когда снимали обе.
  Файлы без пары перечисляются в отчёте отдельно.
- **Переключение** каждые `--switch` секунд (5), границы кусков выровнены по кадрам. Отсчёт начинается
  заново, когда появляется вторая камера, и первой показывается она.
- **Звук** — от камеры на экране, с короткими затуханиями на стыках. `--audio A` или `--audio B` —
  всегда от этой камеры, когда у неё есть звук; иначе от камеры на экране.
- **Имя ролика**: `<самый ранний файл группы>_multicam_<число файлов>.mp4`, рядом с этим файлом.
  Разрешение — наибольшее в группе (`--resolution`), частота кадров — наибольшая (`--fps`),
  кодирование x264 (`--crf` 20, `--preset` medium, `--max-bitrate`). В метаданные записывается
  время начала группы, так что ролик можно класть в каталог события для avtokino.
- **Отчёт**: файлы с временем съёмки, сверка каждой пары с уверенностью, состав групп и монтаж
  по секундам (камера, файл, отрезок файла, источник звука). Выводится на экран и сохраняется в
  `multicam_<дата>_<время>.log`. `--dry-run` — только отчёт, без сборки.
- Сомнительные сдвиги по умолчанию не используются (`--accept-doubtful` — использовать).
- Работа: `--jobs` (2 куска параллельно), `--temp-dir`.

### pano360: ролик из панорам 360

Собирает ролик из панорам 360 (фото и видео в развёртке 2:1, например Samsung Gear 360) каталога.
Порядок — по времени съёмки, затем по имени. Файлы не 2:1 пропускаются.

```bash
python -m avtokino.tools pano360 E:\photo\360                      # обычный кадр, камера крутится
python -m avtokino.tools pano360 E:\photo\360 "360_*" --rotation 12 --direction left --pitch -10
python -m avtokino.tools pano360 E:\photo\360 --mode 360            # полноценный ролик 360
```

- **`--mode flat`** (по умолчанию) — обычный кадр 16:9 (`--resolution`, 1920x1080), камера поворачивается
  по кругу: один оборот за `--rotation` секунд (8), `--direction right|left`, угол обзора `--fov` (90°),
  наклон `--pitch` (0°, плюс — вверх), начальное направление `--yaw` (0 — центр панорамы). Поворот
  продолжается от файла к файлу без скачков (`--no-continuous` — каждый файл с начального направления).
  Крутятся и фото, и видео. Чтобы поворот шёл ровно, без подёргиваний, время оборота округляется до
  целого числа кадров, а панорама слегка растягивается по ширине так, чтобы окно сдвигалось каждый кадр
  на одинаковое целое число пикселей (8 с при 29.97 кадр/с дают 240 кадров = 8.008 с).
- **`--mode 360`** — ролик 360 в развёртке 2:1 (по умолчанию размером с самое большое видео) с пометкой
  сферической проекции в двух форматах — новом (sv3d, YouTube, VLC) и старом XMP, как у Gear 360
  ActionDirector (GoPro Player и другие настольные плееры): ролик можно вращать.
- Фото показываются по `--photo-duration` секунд (15). Звук — из видео, под фото тишина.
- Результат: `<каталог>_pano.mp4` или `<каталог>_pano360.mp4` в том же каталоге (повтор — `_v2`).
  `--dry-run` — только список и порядок файлов. Кодирование: `--crf` (20), `--preset`, `--max-bitrate`,
  `--fps`, `--jobs` (2 файла параллельно).
- У видео Gear 360, склеенных в ActionDirector, в метаданных записана дата склейки, а не съёмки,
  поэтому в порядке файлов они могут оказаться не на своём месте.
